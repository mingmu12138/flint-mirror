燧镜的模组接口要求
版本 v1.10.3 · 2026-11-24 · 作者：布鲁托是小馋猫
适用：给燧镜写扩展包（.sjmod）的人或 AI 助手 —— 照着做就能装、能跑、能通过自检

==================================================================
零、这份文件是什么
==================================================================
宿主（燧镜）侧的接口已经定稿并实测通过，不需要模组侧再提需求。
下面写清楚：你能用哪些东西、哪些是硬边界、包里必须带什么、怎么自检。
第六节是一整段可直接粘给模组助手的提示词。

==================================================================
一、接口定稿（拿到的能力，逐条都已实现）
==================================================================
host.spec                 id / name / version / api_version / author / description / kind / permissions
host.app_version          宿主版本，如 "v1.10.3"
host.api_version          "1"
host.log                  info(msg) / warn(msg) / error(msg, exc=False)
host.cfg                  get(key, default) / set(key, value)   存 mods_data\<id>\config.json
host.paths.data_dir       <应用目录>\mods_data\<id>    可写，缓存/下载都往这
host.paths.resource       模组自己的目录（= manifest.json 所在目录）只读
host.paths.assets         <模组目录>\assets            只读，随包文件都在这
host.notify               notify(title, text, level="info")      权限 notify
host.ui                   register_page(key, builder) / unregister_page(key)   权限 ui.page
host.hotkey               register(combo, fn) / unregister(combo)  权限 hotkey，形如 "Ctrl+Alt+V"
host.events               on(name, fn) / off(name, fn) / emit(name, **kw)   权限 events
host.schedule             every(seconds, fn)                       权限 schedule
host.shell                launch(path, args=None) -> bool                      权限 shell
                          capture(args: list, timeout=30) -> (code, out, err)  权限 shell
                          code: >=0 为退出码，-1 超时，-2 起不来；同步，会占用调用线程

命名空间里只有这些。core / gui 的内部对象一个都不给你，也不该去 import。
接口自审计脚本：tool/mod_api_audit.py（文档 vs 实现逐条比对，当前输出"文档写了代码没有：无 / 代码有文档没写：无 / 权限名对齐"）。

==================================================================
二、已经实测过的（不是纸面承诺）
==================================================================
用「平台视频」这个模组在源码环境跑完整链路，结果：
  · load → enable → disable → unload 四个钩子全部 True
  · host.paths.assets 解析到 <模组目录>\assets，存在
  · assets\pylibs 加进 sys.path 后，yt-dlp 从包里 import 成功
  · host.shell.capture([ffmpeg, "-version"], 15) 返回码 0，拿到版本输出
  · 真下载 B 站 BV1GJ411x7h7：66.5MB 视频 + 5.2MB 音频，转码 H.264+AAC，51 秒，成品 94.4MB
  · 停用后 temp 目录清掉、悬浮窗销毁；卸载时把 sys.path 里那条摘掉、bin 目录删掉
  · register_page 的 key 会出现在卡片「⋯」菜单，点开是 560×420 对话框
  · 热键 Ctrl+Alt+V 注册成功，热键回调只在启用的模组里生效

==================================================================
三、硬边界（越界就是不合格，宿主不会替你兜）
==================================================================
1. 不能 import 宿主内部（core、gui、utils 等）。只认 host 对象。
2. 不能造 QMainWindow。自建悬浮窗用 QWidget + FramelessWindowHint + WindowStaysOnTopHint + Qt.Tool。
3. 不能依赖 game.started 这类宿主事件来决定显隐。宿主事件只读不改，game.* 事件是"通知"不是"指令"。
4. 业务逻辑放 on_enable，清理放 on_disable。on_load 只做登记（register_page / hotkey.register / sys.path 挂载）。
5. on_disable 必须能当场掐断：线程 stop + join(3)、子进程 terminate、窗口 hide/close/deleteLater、temp 删掉。
   不能出现"停用了但后台还在下载/还在转码"。
6. 停用后宿主会从「⋯」菜单撤掉界面页入口；你的界面 builder 也要能在停用状态下被安全调用（不要假设窗口一定存在）。
7. 不申请没用到的东西。申请了就写进 manifest 的 permissions，用户安装前会看到中文解释。
8. 包内 .exe / .dll / .bat 只能放 assets 下，且必须申请 shell 权限。
9. 单个随包程序 > 60MB 会被提示包太大；能裁就裁，不要塞完整版 ffmpeg 全家桶。
10. 顶层代码不许 import 重依赖（yt-dlp、cv2 之类）。放函数里懒加载，失败给一句人话提示，别让整个模组加载不起来。
11. 不要在包根放 exe、不要多套一层目录、不要带 __pycache__ / .pyc。
12. 不要自己在模组里做"检查更新/下载安装包"这类会替换自身文件的事。

==================================================================
四、包里必须带什么（清单）
==================================================================
manifest.json（包最外层）  必填 8 字段 + apiVersion:"1"
  id        小写，正则 ^[a-z0-9][a-z0-9_.\-]{1,39}$，建议倒序域名 com.xxx.yyy
  kind      package（普通扩展包）
  permissions  只列真用到的，取值仅限：
               notify / ui.page / hotkey / shell / events / schedule / fs.data
main.py（包最外层）  四个钩子 on_load(host) / on_enable() / on_disable() / on_unload()
assets\   随包资源
  ├─ lib\<包名>\           纯 Python 依赖（yt_dlp 等），宿主在 on_load 前自动挂进 sys.path
  │                        （目录名叫 pylibs 也认，两种写法都行）
  ├─ bin\<程序>.exe        可选的命令行程序（ffmpeg 之类）
  └─ 图标、模板等静态文件

下载类功能的最低要求（以 yt-dlp 为例）：
  · yt-dlp 放 assets\lib\yt_dlp\（或 pylibs\yt_dlp\），不要指望用户装
  · 转码用的 ffmpeg 优先从 data_dir\bin\ffmpeg.exe 找，再找 PATH，再找包里 assets\bin\
  · 找到了先用 host.shell.capture([exe, "-version"], 15) 验一遍，返回码 0 才往下走
  · 找不到就给三条人话指引（放哪、从哪下、重启模组），不要抛英文 traceback
  · 不要自己在 on_load 里 sys.path.insert —— 宿主已经挂了；只有老宿主才需要自己兜一手
  · 长任务用 subprocess.Popen 自己管进程，才能被 on_disable 立刻 terminate；capture 是同步的，不能用来跑几十秒的转码

==================================================================
六、提示词（整段复制给模组助手）
==================================================================
【角色】
你在给「燧镜」写一个第三方扩展包（.sjmod）。宿主的接口已经定稿，下面这份就是全部边界，
不要再向宿主提新接口需求，也不要改宿主代码。

【宿主能给你的（只有这些）】
host.spec / host.app_version / host.api_version / host.log / host.cfg /
host.paths.data_dir(可写) / host.paths.resource(只读) / host.paths.assets(只读) /
host.notify(title,text,level) / host.ui.register_page(key,builder) / host.ui.unregister_page(key) /
host.hotkey.register(combo,fn) / host.hotkey.unregister(combo) /
host.events.on/off/emit / host.schedule.every(seconds,fn) /
host.shell.launch(path,args) -> bool / host.shell.capture(args, timeout=30) -> (code,out,err)
权限只有 7 种：notify / ui.page / hotkey / shell / events / schedule / fs.data。申请什么写进 manifest，用户装前会看到。

【结构】
包最外层：manifest.json + main.py + assets\
manifest 必填：id、name、version、apiVersion("1")、author、description、kind("package")、permissions
四个钩子：on_load(host) 只登记；on_enable() 起业务；on_disable() 全部收干净；on_unload() 再兜底。
随包依赖：纯 Python 包放 assets\lib\<包名>\（或 pylibs\<包名>\），宿主在 on_load 之前就把它挂进 sys.path，
          直接 import 即可，不要自己再 sys.path.insert；
命令行程序放 assets\bin\，用 host.shell.capture 调用，并且 manifest 必须申请 shell。

【红线】
不 import 宿主内部（core/gui）；不造 QMainWindow（浮窗用 QWidget + Frameless + StaysOnTop + Qt.Tool）；
不依赖 game.started 决定显隐；on_disable 必须让线程结束、子进程 terminate、窗口销毁、temp 清空；
顶层不 import 重依赖（懒加载）；包内 exe 只在 assets 下；不带 __pycache__/.pyc；不多套一层目录。

【自检】
tool\make_sjmod.py 打包 → tool\mod_test.py 判定「通过，可以装」→ 再人工核对
grep 宿主内部零命中、QMainWindow 只在注释、停用后无残留线程与 temp。
把这两步的输出原样贴回来。
